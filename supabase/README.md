# Supabase — content backend

The storefront reads all content through `ContentRepository`
(`src/lib/content/`). It uses **Supabase** when `NEXT_PUBLIC_SUPABASE_URL` and
`NEXT_PUBLIC_SUPABASE_ANON_KEY` are set, and falls back to the in-memory
`MockContentRepository` otherwise — so the app and the tests run with no
backend.

## Files

| File | What it is |
| --- | --- |
| `migrations/20260910120000_content_schema.sql` | Tables, indexes, `updated_at` triggers, RLS + public-read policies. |
| `seed.sql` | Sample catalogue (the 6 mock perfumes + site settings). Generated by `scripts/generate-supabase-seed.mts`; regenerate with `npm run seed:generate` if the sample data changes. |

The schema stores **image references only** (`perfume_images.path` — a Storage
object key, or an absolute/local URL). No binary data, no 3D models.

## Apply it

### With the Supabase CLI (recommended)

```bash
supabase init          # if you haven't already (creates supabase/config.toml)
supabase link --project-ref <your-project-ref>
supabase db push       # applies migrations/
psql "$DATABASE_URL" -f supabase/seed.sql   # or: supabase db reset (also runs seed.sql)
```

### Without the CLI

1. Supabase dashboard → **SQL Editor** → paste and run
   `migrations/20260910120000_content_schema.sql`.
2. Then paste and run `seed.sql`.

### Then

```bash
cp .env.example .env.local
# fill NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY
npm run dev
```

The site now serves DB content; edit rows in the dashboard and they appear
after the page's `revalidate` window (1 h) or an on-demand revalidation.

## Row Level Security

RLS is **on** for every table. Policies grant `select` to the anon role for
published content only (`perfumes.is_published = true`, and its child rows via
`exists (…)`). **No `insert` / `update` / `delete` policy exists**, so anonymous
and signed-in users cannot write anything. The service-role key bypasses RLS
and is the only write path today (server-side, never shipped to the browser).

The Admin phase will add authenticated-writer policies — the migration ends
with a commented template (`is_admin()` + an `admins` allow-list table). Do not
enable those until admin auth is built.

## Image storage (later phase)

Perfume photography will live in a public Storage bucket named
**`perfume-images`**. `next.config.ts` already allow-lists
`https://<project>.supabase.co/storage/v1/object/public/**` for `next/image`
when Supabase is configured. Uploading is **not** part of this phase.
